- **Реализация возможности редактирования и удаления транзакций в Журнале с пересчетом остатков:**
  - **Безопасное удаление транзакций (`deleteTransaction`):** Разработана логика автоматического отката складских остатков по типам транзакций. Откат прихода (`IN`) и возврата (`RETURN`) блокируется при наличии частичных отгрузок с этой партии для предотвращения отрицательных остатков. При отмене расхода (`OUT`) списанный вес возвращается в исходную партию; если партия была удалена при списании до нуля, она автоматически воссоздается в исходной камере на основе исторических данных транзакции. При отмене перемещения (`MOVE`) вес возвращается в исходную партию отправления и вычитается из целевой партии.
  - **Интеллектуальное редактирование транзакций (`updateTransaction`):** Реализован дельта-пересчет весов (`diff = newQty - oldQty`) при изменении количества в транзакции, гарантирующий математическую строгость баланса без дублирования ID.
  - **Решение проблемы целостности БД Supabase (RCA):** Устранена ошибка нарушения ограничений внешнего ключа (foreign key constraint) PostgreSQL, возникавшая при параллельном удалении транзакций и связанных партий. Оптимизирован порядок запросов: сначала транзакция в Supabase, затем выполняются манипуляции над связанными партиями.
  - **Премиальный интерфейс Журнала (`Journal.tsx`):** Интегрированы кнопки действий (редактирование - карандаш, удаление - корзина) с разграничением прав доступа: операции доступны только для роли `ADMIN` (вход по паролю `admin2026`). ## 🌐 Спецификация структуры БД для перевода системы в облако (Онлайн-БД)

Для развертывания решения MeatSync в реальной облачной среде (PostgreSQL, MySQL или NoSQL вроде Google Cloud Firestore) потребуется создать **6 основных сущностей** (таблиц или коллекций). 

Ниже приводится детальное описание структуры:

### 1. Таблица `products` (Номенклатура продукции)
*Учет перечня производимых мясных изделий, базовых сроков и характеристик сырья.*
* **`id`** (UUID/String, PK) — Уникальный идентификатор позиции.
* **`sku`** (String, Unique, Index) — Автогенерируемый артикул (например, `SV-BL-01`).
* **`name`** (String) — Наименование товара (например, "Окорок свиной б/к").
* **`category`** (String) — Категория категории (Свинина, Говядина и т.д.).
* **`rawMaterial`** (String) — Группа сырья (Свинина, Говядина, Птица, Субпродукты...).
* **`packagingType`** (String) — Метод фасовки (Блочка, Лотки, Вакуум, Полутуши...).
* **`defaultShelfLifeDays`** (Integer) — Срок годности по умолчанию (дней).
* **`notifyBeforeDays`** (Integer) — Настраиваемый порог предупреждения о просрочке (дней).

### 2. Таблица `locations` (Склады и камеры хранения)
*Статический реестр складских мощностей и предельного тоннажа.*
* **`id`** (String, PK) — Код локации (например, `loc_returns_1`, `loc_shock_1`).
* **`name`** (String) — Название зоны (например, "Камера шоковой заморозки").
* **`type`** (String) — Функциональный тип хранения (`main_fridge`, `reefer`, `shock_freezer`, `returns`).
* **`capacityKg`** (Integer) — Максимальная емкость камеры (в кг) для расчета переполнения.

### 3. Таблица `batches` (Партии на складе)
*Документирование фактического поштучного/паллетного веса сырья на остатках в реальном времени.*
* **`id`** (UUID/String, PK) — Уникальный штрихкод партии.
* **`productId`** (UUID/String, FK → `products.id`) — Ссылка на номенклатурную карту.
* **`locationId`** (String, FK → `locations.id`) — Ссылка на текущую камеру нахождения.
* **`quantityKg`** (Float) — Текущий физический вес в кг.
* **`initialQuantityKg`** (Float) — Первоначальный вес при оприходовании/производстве.
* **`receivedAt`** (DateTime) — Дата выпуска / прибытия.
* **`expiresAt`** (DateTime, Index) — Срок годности партии.
* **`isReturn`** (Boolean, Default: false) — Флаг принадлежности партии к категории возвратов/карантина.
* **`returnedByBuyerId`** (UUID/String, Nullable, FK → `buyers.id`) — Ссылка на контрагента, вернувшего товар.
* **`returnReason`** (String, Nullable) — Зафиксированная причина нарекания по качеству.

### 4. Таблица `buyers` (Контрагенты / Покупатели)
*Реестр заказчиков для дистрибуции партий.*
* **`id`** (UUID/String, PK) — Уникальный идентификатор покупателя.
* **`name`** (String) — Имя компании / ИП (например, "ООО Мясной Двор").
* **`inn`** (String, Nullable, Index) — ИНН организации для юридического контроля.
* **`phone`** (String, Nullable) — Контактный номер логиста.

### 5. Таблица `transactions` (Журнал перемещений и операций)
*Неизменяемый логистический след движения сырья и готовой продукции (Audit Trail).*
* **`id`** (UUID/String, PK) — Номер проводки.
* **`type`** (String) — Тип транзакции (`IN` — приемка, `OUT` — отгрузка, `MOVE` — переброс, `RETURN` — возврат).
* **`productId`** (UUID/String, FK → `products.id`) — Какой товар двигался.
* **`quantityKg`** (Float) — Масса движения (кг).
* **`date`** (DateTime, Index) — Время совершения хозяйственной операции.
* **`batchId`** (UUID/String, FK → `batches.id`) — Какая именно физическая партия задействована.
* **`fromLocationId`** (String, Nullable, FK) — Откуда отправлено (для движений).
* **`toLocationId`** (String, Nullable, FK) — Куда принято (для приемки и движений).
* **`outcomeType`** (String, Nullable) — Метод завершения партии (`sale` — продажа, `waste` — брак, `mpc` — мясопереработка).
* **`buyerId`** (UUID/String, Nullable, FK → `buyers.id`) — Клиент-получатель или инициатор возврата.
* **`notes`** (Text) — Пометки весовщика или технолога.

### 6. Таблица `users_auth` (Пользователи и уровни доступа)
*Параметры безопасности и ролевые политики RBAC.*
* **`id`** (UUID/String, PK) — ID сотрудника.
* **`username`** (String, Unique) — Логин для входа.
* **`passwordHash`** (String) — Безопасный Bcrypt-хэш пароля.
* **`role`** (String) — Назначенная роль доступа (`ADMIN`, `MANAGER`, `WORKER`).
