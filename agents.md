# Регламент Оркестрации и Безопасности (V2: Ultra-Secure)

## 1. Принципы Безопасности
- Любые изменения в бизнес-логике проекта производятся исключительно при наличии соответствующих Unit-тестов.
- Изменение существующего кода требует предварительного согласования через блок "Current Logic Summary".
- Файл `PROJECT_LOG.md` обновляется строго по прямой команде пользователя. Автоматическая запись логов запрещена.

## 2. Роли и Зоны Ответственности
- **Архитектор (Пользователь):** Принимает архитектурные решения, утверждает изменения, дает команды на запись логов.
- **Навигатор (ИИ-Агент):** Анализирует систему, предлагает решения, пишет тесты и код, контролирует целостность системы.

## 3. Процедура Изменений
1. **Анализ:** Определение целевого файла и логики.
2. **Logic Summary:** Описание текущей и новой логики в чате.
3. **Согласование:** Ожидание подтверждения ("Применяй"/"Ок").
4. **Реализация:** Запись файлов кода и сопутствующих Unit-тестов.
5. **Верификация:** Запуск тестов, проверка отсутствия регрессий. Если все тесты пройдены успешно — выполнить коммит (строго на русском языке) и автоматическую отправку изменений в репозиторий (git push).
6. **Фиксация:** Предоставление лога сессии для подтверждения пользователем.

## 4. Работа с Git и Деплой
- Для развертывания изменений в рабочем окружении (GitHub Pages) код должен быть отправлен на GitHub.
- Все сообщения коммитов Git (commit messages) пишутся строго на русском языке.
- Автоматическая отправка: При успешном прохождении тестов на шаге Верификации коммит и пуш на GitHub выполняются ИИ-Агентом автоматически без ожидания напоминаний.

## 5. Предотвращение ссылочных мутаций и правила отладки
* **Иммутабельность по умолчанию (Immutable by default):** Любое слияние данных из разных источников (клиент, сервер, облако) должно выполняться строго с клонированием объектов (например, через `.map(x => ({ ...x }))` или `structuredClone()`), чтобы избежать случайной мутации ссылок в оперативной памяти Node.js/React.
* **Интеграционное тестирование:** При тестировании синхронизации тесты должны проверять полную цепочку (Data Flow): от симуляции изменения поля на клиенте до детекции разницы и проверки отправки (upsert) на сервер.
* **Рантайм-диагностика:** В случае сбоев синхронизации запрещено полагаться только на теоретические выводы. ИИ-Агент обязан запускать точечные диагностические скрипты для проверки фактического состояния данных в файлах на диске и в облаке.
